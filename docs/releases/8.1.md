## Upgrade considerations - changes affecting Wagtail customizations

### Site scope for page serve and preview

Wagtail binds a request-scoped site around deferred template rendering via an :ref:`on_serve_page <on_serve_page>` hook for front-end page serve (identified from the request hostname) and at preview boundaries (identified from the page being previewed, not the request hostname). Password-required page views use the page's site. That covers `{{ page.body|richtext }}` and other template code that expands page links without an explicit `request`. For custom views that return a `TemplateResponse`, call `wagtail.models.sites.bind_site_scope_on_render()` on the response before it is rendered.

`Page.get_url_parts()` and `Page.get_url()` are unchanged when you pass `request` explicitly. When no `request` is passed, they use the bound site if one is active.

This fixes multi-site page links in rich text without threading `request` through `expand_db_html()`, the `|richtext` filter, or rewrite handlers. Django filters cannot access the template context, so a `request` parameter on `expand_db_html()` would not help `{{ page.body|richtext }}` anyway; binding the site at render boundaries reuses the same site identification that `Page.get_url()` already performs. See :ref:`rich_text_page_links_multi_site`.
